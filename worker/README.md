# 🤍 Бот трекера на Cloudflare Workers

Отдельная облачная версия Node.js-бота из `bot/`. Получает обновления Telegram
через вебхук и не требует включённого компьютера. Сайт Vercel от неё независим.

## Как устроено

- `POST /telegram` принимает только запросы с правильным секретным заголовком.
- Durable Object `TrackerStorage` сохраняет задачи, дневные отметки, историю и
  ожидаемый ввод в постоянной SQLite-базе Cloudflare.
- Повторная доставка одного `update_id` не переключает отметку второй раз.
  Ответы Telegram сохраняются в очереди до успешной отправки; после сбоя сети
  возможна повторная доставка ответа, но изменение данных выполняется один раз.
- Запросы обрабатываются последовательно. Данные пользователей разделены по ID.
- Используется та же модель 10 клеток и дней, что в локальном Node.js-боте.
- День меняется в часовом поясе `TIMEZONE` (по умолчанию `Europe/Moscow`).

## Рабочий адрес

`https://ten-tasks-bot.hatam-bot-worker.workers.dev`

Секреты `BOT_TOKEN`, `OWNER_ID` и `WEBHOOK_SECRET` должны быть настроены в этом
Worker. Их значений нет в коде и Git. В локальном `bot/.env` могут оставаться
настройки для отладки, однако Worker их автоматически не читает.

## Установка и проверка кода

Нужен Node.js 24 для локальных тестов SQLite и Wrangler.

```sh
cd worker
npm ci
npm test
```

Тесты подменяют Telegram, но используют настоящий SQLite. Проверяются защита
вебхука, сохранение ожидаемого ввода после перезапуска, добавление, изменение,
удаление, отчёты, изоляция пользователей и повторная доставка обновлений.
Обычные тесты дней и процентов также доступны через `cd ../bot && npm test`.

## Первая публикация

1. Авторизуйтесь в Cloudflare через `npx wrangler login` либо используйте
   настроенный `CLOUDFLARE_API_TOKEN`. Для настроенного облачного окружения
   интерактивный вход не нужен.
2. Выполните `npm run deploy`. Wrangler создаст SQLite Durable Object по миграции
   в `wrangler.jsonc` (платный KV или внешняя база не нужны).
3. В Cloudflare откройте **Workers & Pages → ten-tasks-bot → Settings → Variables
   and Secrets**. Добавьте `BOT_TOKEN` и `OWNER_ID` с типом **Secret**.
   Используйте токен именно бота трекера, не бота «Хатм».
4. Сгенерируйте защиту вебхука, если файл ещё не существует:

   ```sh
   node -e "const fs=require('node:fs');if(!fs.existsSync('.webhook-secret'))fs.writeFileSync('.webhook-secret',require('node:crypto').randomBytes(32).toString('hex'),{mode:0o600})"
   ```

   Загрузите это значение в секрет `WEBHOOK_SECRET`. В Linux / CMD:

   ```sh
   npx wrangler secret put WEBHOOK_SECRET < .webhook-secret
   ```

   В PowerShell: `Get-Content .webhook-secret | npx wrangler secret put WEBHOOK_SECRET`.
   Файл `.webhook-secret` игнорируется Git, не публикуйте его.

5. Остановите локальный процесс трекера (`Ctrl+C`), чтобы long polling не
   конфликтовал с вебхуком. После переключения не запускайте `bot/npm start`
   с тем же токеном: Telegraf может удалить вебхук.
6. Привяжите вебхук:

   ```sh
   npm run setup -- https://ten-tasks-bot.hatam-bot-worker.workers.dev
   ```

   Защищённая команда проверит токен через `getMe`, установит URL и проверит его
   через `getWebhookInfo`. Старые обновления не удаляются. Если у токена уже есть
   другой вебхук, настройка откажется его перезаписывать: сначала проверьте токен.
7. Отправьте `/start` в личном чате бота. Добавьте дело, завершите его и проверьте
   **10%** в «Прогресс». Проверьте недельный отчёт.
8. Выключите локальный бот и убедитесь, что ответы продолжают приходить.

`GET /` возвращает только статус конфигурации, без токена, ID владельца и данных
пользователей. `configured: true` означает наличие настроек, а не успешную
регистрацию вебхука — она отдельно проверяется командой setup.

## Последующие обновления

После изменения кода: `npm test`, затем `npm run deploy`. Секреты и SQLite-данные
сохраняются. Повторная привязка вебхука не нужна, если адрес и секрет не менялись.
Не удаляйте Worker и его Durable Object: в нём хранится история.

## Уже существующие дела на компьютере

Локальный `bot/storage/tasks.json` автоматически не переносится в Cloudflare.
Сохраните его резервную копию. Новая облачная база изначально пустая. Для переноса
существующих дел нужен отдельный импорт; не публикуйте этот файл в GitHub.

## Если бот не отвечает

- `configured: false`: проверьте все три секрета и правильность числового OWNER_ID.
- `setup` не проходит: проверьте токен бота и текущий вебхук.
- После локального запуска перестал работать вебхук: остановите `npm start` и
  снова выполните `npm run setup -- <адрес>`.
- Не передавайте токены и необработанные сетевые ошибки в общие логи.

Папка `worker`, локальные `.env`, секреты и базы исключены из статического деплоя
Vercel через `.vercelignore`.
